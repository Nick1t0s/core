### Telegram

Скраппер Telegram — демон, создаваемый пользователем через его кабинет, как скраппер YouTube. Режимы выполняются последовательно, записи отправляются в core по общим правилам (см. «Отправка в core»), записи с файлами больше max_file_size заносятся в таблицу пропущенных по размеру. После создания экземпляр поднимает свой сайт на FastAPI, с публикацией и правилами входа по выбору владельца; сессия core не обязательна. Своего Telegram-бота у скраппера нет.

#### Доступ к Telegram

История каналов и чатов читается через MTProto (например, Telethon или Pyrogram) от имени пользовательского аккаунта: Bot API не умеет читать историю каналов, в которых нет бота. Файл сессии — секрет, в репозиторий не попадает. При `FloodWait` скраппер ждёт указанное время и продолжает.

#### Идентификация записи

- Record — одно сообщение канала или чата. Альбом (сообщения с общим `grouped_id`) — один record с несколькими файлами.
- `source_id` = `telegram`.
- Owner core подставляет из регистрации экземпляра скраппера; trust_level назначается по настройкам его сайта. Ключ записи в core — (owner, source_id, source_url). Проверки существования относятся только к owner скраппера.
- `source_url` в каноническом виде:
  - публичные каналы и супергруппы — `https://t.me/<username>/<message_id>`;
  - приватные каналы и супергруппы — `https://t.me/c/<internal_id>/<message_id>`;
  - личные диалоги и обычные (не супер-) группы — у них нет ссылок t.me, а id сообщений свои у каждого аккаунта, поэтому используется псевдоссылка `tg://chat/<peer_id>/<message_id>`. Она уникальна и не меняется для нашего аккаунта, но по ней нельзя перейти.

  Для альбома берётся ссылка на первое сообщение.
- `text` = текст или подпись, `author` = канал или отправитель, `source_created_at` = дата отправки сообщения.
- `parent_source_url` = сообщение, на которое это ответ. У пересланных сообщений оригинал записывается в `metadata`, а ключ строится по текущему сообщению.

#### Режимы работы

- **Сканер каналов** — обходит список каналов. Для каждого хранится `last_message_id`: скраппер читает только новые сообщения, а при первом запуске — всю историю.
- **Сканер чатов** — то же самое для групп и личных диалогов из явного списка.

Перед добавлением сообщения в очередь отправки проверяется, что его нет в очереди, в таблице пропущенных по размеру и в core (по `source_id` и `source_url`). Проверка в core нужна и при наличии `last_message_id`, на случай сброса состояния.

Из-за `last_message_id` сканеры не увидят заново запись, удалённую вручную в core (см. «Записи с ошибкой и повторная отправка»). Есть идея на каждом проходе брать все id сообщений группы или чата и сверять их с core; пока это открытый вопрос.

#### Что скачивать

Для каждого канала или чата настраивается глубина: только текст, текст и фото, или всё (включая видео и документы). Отдельного ограничения по размеру у глубины нет: действует общее правило `max_file_size` — сообщение с файлом больше него пропускается целиком и заносится в таблицу пропущенных по размеру (на практике недостижимо: лимит файлов Telegram 2–4 ГБ). Значение по умолчанию в конфиге задаётся для пользователя, а не для системы: оно соответствует положению переключателя при добавлении канала в админке, поэтому поле в списке каналов не бывает пустым. Голосовые сообщения и кружки идут как аудио на транскрибацию.

#### Ограничения

- Отредактированные сообщения не перечитываются.
- Удалённые на источнике сообщения не отслеживаются.

#### Сайт скраппера

- статистика по очереди отправки в core и список сообщений, пропущенных по размеру;
- список каналов и чатов, в том числе выбор глубины скачивания при добавлении;
- включение и выключение режимов работы;
- настройка trust_level отправляемых записей.
