### YouTube

Скраппер YouTube — демон. У него несколько режимов работы, каждый включается отдельно в конфиге. Режимы выполняются последовательно, а не параллельно, чтобы не получить бан от YouTube.

#### Архитектура

Скраппер состоит из следующих частей:

- **Демон** — по очереди обходит включённые режимы, скачивает видео и кладёт их в очередь отправки в core.
- **Очередь загрузки** — хранится в памяти, не персистентна: после перезагрузки восстанавливается повторным сканированием.
- **Очередь отправки в core** — хранится в SQLite, персистентна (переживает перезагрузку).
- **Папка с файлами** — специальная папка внутри скраппера, где лежат файлы видео, ожидающих отправки в core.
- **Таблица пропущенных по размеру** — SQLite, см. «Файлы больше `max_file_size`».
- **Отправка в core** — скраппер сам отправляет записи в core (см. «Отправка в core»).
- **Telegram-бот** — принимает ссылки от пользователя (см. ниже).
- **Админка** — веб-интерфейс на FastAPI, доступный только из локальной сети.

#### Идентификация записи

- `source` = `youtube`.
- `source_url` = ссылка на видео в каноническом виде: `https://www.youtube.com/watch?v=<video_id>`. Ссылки вида `youtu.be/…` и `/shorts/…` приводятся к этому виду, иначе одно и то же видео из разных режимов получило бы разные ключи.
- `text` = склейка названия и описания видео, `title` = название, `author` = канал.
- `source_created_at` = дата публикации видео, `scraped_at` = момент получения записи скраппером.
- В `metadata` кладутся длительность и признак shorts.

#### Режимы работы

- **Сканер каналов** — обходит список YouTube-каналов и выкачивает все их видео.
- **Сканер плейлистов** — обходит список плейлистов и выкачивает все видео из каждого.
- **Сканер истории** — получает доступ к аккаунту YouTube и на каждом проходе читает всю доступную историю просмотров, сверяет её с core и выкачивает просмотренные видео, которых там нет.
- **Telegram-бот** — принимает ссылки на видео, которые пользователь отправляет ему в чат, и ставит их на загрузку (см. «Telegram-бот»).

#### Устройство загрузчика

Скраппер работает с двумя очередями:

- **очередь загрузки** — содержит объекты `youtube_video`; изначально в них есть только ссылка;
- **очередь отправки в core** — содержит те же объекты после скачивания: с аудио-/видеофайлом (см. ниже) и метаданными.

Порядок работы:

1. Демон по очереди обходит режимы, включённые в конфиге: каждый режим сканирует свой источник и находит видео.
2. Перед добавлением видео в очередь загрузки проверяется, что его нет ни в одной из двух очередей, ни в таблице пропущенных по размеру и ни в core. Проверка в core выполняется по `source` и `source_url`.
3. Пока суммарный размер скачанных файлов меньше X ГБ, загрузчик берёт видео из очереди загрузки и скачивает его. Перед скачиванием ещё раз проверяется по `source` и `source_url`, что видео нет в core и в очереди отправки в core. Если YouTube сообщает размер файла и он больше `max_file_size`, видео не скачивается, а заносится в таблицу пропущенных по размеру.
4. Пока видео не загружено полностью, оно остаётся в очереди загрузки. Как только загрузка завершена, размер проверяется ещё раз: если файл больше `max_file_size`, он удаляется, а видео заносится в таблицу пропущенных по размеру. Иначе объект сразу переносится в очередь отправки в core.

#### Аудио или видео

Для каждого режима настраивается, что именно скачивать: только аудио или видео целиком.

- **Сканер каналов** хранит режим загрузки для каждого канала в списке каналов. В конфиге задаётся значение по умолчанию. Это значение по умолчанию именно для пользователя, а не для системы: оно соответствует положению переключателя при добавлении канала в админке, поэтому поле режима в списке каналов не может быть пустым.
- **Сканер плейлистов** работает так же, как сканер каналов.
- **Сканер истории** настраивается отдельно для shorts и для обычных видео.
- **Telegram-бот** запрашивает режим отдельно для каждого видео.

#### Передача видео в core

Очередь отправки в core — SQLite, FIFO. Записи отправляются по общим правилам (см. «Отправка в core»): в core одновременно не больше K незавершённых записей скраппера, запись и её файлы остаются у скраппера, пока core не ответит `done` или `error`, а на `unknown` запись отправляется заново. При `error` исходник остаётся в core, повторно запись не отправляется, пока её не удалят вручную в веб-интерфейсе core (см. «Записи с ошибкой и повторная отправка»).

#### Telegram-бот

- Пользователь присылает боту ссылку на видео, бот спрашивает режим загрузки (аудио или видео) и ставит видео на загрузку.
- Бот хранит в SQLite список присланного, что ещё не завершено в core. Список переживает перезагрузку: ссылки от бота нельзя восстановить повторным сканированием, а очередь загрузки хранится в памяти.
- Когда core отвечает `done`, элемент удаляется из списка.
- Когда core отвечает `error`, бот явно сообщает об этом пользователю в чате (с текстом ошибки) и удаляет элемент из списка. Чтобы отправить видео заново, запись нужно удалить в веб-интерфейсе core и снова прислать ссылку боту.
- Если видео пропущено по размеру, бот тоже сообщает об этом пользователю.

#### Админка

Админка написана на FastAPI и открывается только из локальной сети. В ней можно:

- смотреть статистику по очередям (загрузки и отправки в core) и список видео, пропущенных по размеру;
- смотреть и редактировать списки каналов и плейлистов, в том числе выбирать режим загрузки (аудио или видео) при добавлении;
- включать и выключать режимы работы.
