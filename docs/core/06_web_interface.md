### 6. Веб-интерфейс core

Для входа нужны логин и пароль. При разрешённой внешней регистрации доступна форма создания пользователя: только логин и пароль либо дополнительно одноразовый код приглашения. Настройки регистрации и правила аутентификации — в разделе 11. Доступ из локальной сети сам по себе прав не даёт.

**Пользовательский кабинет** показывает только данные вошедшего пользователя. В нём можно:

- создавать и настраивать свои агенты: каждый режим имеет собственный agent_id и trust_level, зарегистрированные в core;
- создавать свои скрапперы и переходить на их собственные сайты настройки; администратор не создаёт скрапперы за пользователя;
- смотреть собственные записи, статусы, trust_level и ошибки: error и error_detail записи и её file, включая ошибки внутри записей в done;
- менять trust_level своих записей и удалять свои записи в любом статусе.

**Административный раздел** управляет пользователями, режимом внешней регистрации и одноразовыми приглашениями. Администратор имеет доступ ко всем данным, в том числе для просмотра ошибок и удаления записей; создание агентов и скрапперов находится в пользовательском кабинете.

Удаляется record целиком, его дерево и задачи — каскадом внешних ключей. Каталоги в хранилище исходных файлов и task_storage удаляет очистка хранилищ, так как записи больше нет в БД (3.3). Удаление не затрагивает отдельные копии материала других пользователей. Отдельные file не удаляются. Фоновый приём и разбор останавливаются для удаляемого record; поздние результаты задач игнорируются (11.5).

Тот же API удаления доступен зарегистрированному агенту только при совпадении owner и строгом условии record.trust_level < agent.trust_level. Поисковые права агента и права сессии человека различаются: агент не может воспользоваться ролью администратора своего владельца.

Перезапуска обработки нет: после удаления скраппер этого владельца на запрос статуса получает unknown и, если снова встретит запись, отправляет её заново с новым record_id. Какие режимы скрапперов встречают запись повторно, описано в разделе «Скрапперы».


#### HTTP-запросы кабинета

Вход — `POST /api/auth/login` с JSON `login`, `password`; регистрация — `POST /api/auth/register` с теми же полями и `invite_code` в режиме приглашений. После входа используются cookie `session` и `X-CSRF-Token` для изменяющих запросов.

Агенты создаются через `POST /api/agents`, скрапперы — `POST /api/scrapers`; списки доступны через GET по тем же путям. Собственные записи — `GET /api/records`, просмотр — `GET /api/records/{record_id}`, изменение уровня — `PATCH /api/records/{record_id}` с JSON `trust_level`, удаление — `DELETE /api/records/{record_id}`.

Административные операции находятся под `/api/admin/`: пользователи, настройки регистрации, приглашения и записи всех владельцев. Полный список эндпоинтов с обязательными полями и ответами — в [HTTP API](../api.md).
