# Воркер transcribe

Распознаёт аудио из base64 через faster-whisper. Один запуск принимает одну
пачку через stdin, загружает модель один раз и последовательно обрабатывает задачи.
HTTP API у воркера нет. Входы декодируются в RAM и передаются в faster-whisper
через `BytesIO`; временные аудиофайлы не создаются. Формат аудио определяется
PyAV/FFmpeg по содержимому байтов, расширение файла и MIME не нужны.

## Файлы и запуск

```text
transcribe/
├── .venv/
├── src/
│   ├── main.py
│   ├── batch.py        # Task и Batch
│   ├── audio.py        # Audio: байты аудиофайла и поток для распознавания
│   ├── config.py
│   └── validation.py
├── config.yaml         # локальный конфиг, исключён из Git
├── config.example.yaml
├── requirements.txt
├── mypy.ini
├── tests/
└── README.md
```

Зависимости указаны в [requirements.txt](requirements.txt). Для локальной
транскрибации используется подготовленное окружение `~/whisper-venv`.
Его зависимости не устанавливаются и не обновляются при запуске воркера.
Из каталога `transcribe`:

```bash
~/whisper-venv/bin/python src/main.py --config config.yaml < batch.json
```

`--config` обязателен. Другие рабочие CLI-параметры отсутствуют; `--help`
показывает справку. Пути к конфигу и файлу `batch.json` могут быть абсолютными
или относительными к текущему рабочему каталогу. Скрипт запускается напрямую
через `src/main.py`. `batch.json` — только пример чтения stdin из оболочки:
вызывающая программа может передавать JSON через pipe без файла на диске.

## Конфигурация

Все четыре поля YAML обязательны, неизвестные поля запрещены, значений
по умолчанию нет. [Пример](config.example.yaml):

```yaml
model: large-v3-turbo
device: cuda
compute_type: float16
language: null
```

`model` — имя модели или локальный каталог, `device` — `cuda`, `cpu` или `auto`,
`compute_type` — непустая строка типа вычислений CTranslate2. Для CPU можно
указать `device: cpu` и `compute_type: int8`. `language: null` включает
автоопределение языка; строка вроде `ru` задаёт язык явно. Проверка конфига
проверяет форму значений, поддержка модели, языка и типа вычислений проверяется
библиотекой при работе.

Модель создаётся с `local_files_only=True`: веса должны быть заранее доступны
в локальном кеше или каталоге из конфига. Сам воркер их не скачивает.

## Вход и выход

В stdin передаётся один JSON-массив UTF-8, затем stdin закрывается:

```json
[
  {"task_id": "1", "audio": "<base64 байтов FLAC>"},
  {"task_id": "2", "audio": "<base64 байтов MP3>"}
]
```

Пачка непустая. У каждой задачи ровно два поля: `task_id` — непустая строка,
уникальная в пачке, `audio` — непустая стандартная base64-строка с байтами
аудиофайла (например MP3, WAV или FLAC), без пробельных символов и префикса
`data:audio/...;base64,`. Старое поле `path` больше не принимается.
Поля `type`, `input` и `mime` не передаются. Неизвестные и повторные JSON-ключи
запрещены. Одна задача передаётся массивом из одного элемента.

Структура всей пачки, ID и base64 проверяются до импорта faster-whisper и загрузки
модели. Аудиоконтейнер декодируется при обработке соответствующей задачи;
некорректное аудио завершает всю пачку ошибкой. `BytesIO` остаётся открытым
до окончания чтения ленивого генератора сегментов, затем закрывается.

JSON, base64 и декодированные байты всей пачки занимают RAM. Base64 увеличивает
размер передачи примерно на треть; ограничения размера пачки здесь не вводятся.

При успехе код завершения — `0`, stdout содержит один JSON-объект:

```json
{
  "1": "[00:01:10] Сегодня мы поговорим про нейросети.\n[00:01:15] Рассмотрим, как работают эмбеддинги.",
  "2": ""
}
```

Ключ — исходный `task_id`, значение — текст. Каждый непустой сегмент Whisper
начинается с новой строки с таймкодом `[ЧЧ:ММ:СС]` относительно начала входного
аудиофайла. Доли секунды отбрасываются. Границы строк определяются сегментами
модели, а не отдельным разбиением на предложения. Пробельные символы внутри
сегмента заменяются одиночными пробелами; пустые сегменты пропускаются.
В JSON переносы строк записаны как `\n`, после разбора JSON это обычные переносы.
Без распознанной речи результат — пустая строка.

Тип хранилища результатов также допускает `None` (в JSON — `null`), но текущий
успешный `Task.transcribe()` всегда записывает строку, включая пустую.
Внешних обёрток `results` и `payload` в stdout нет.

## Классы и ошибки

- `Audio.from_base64()` декодирует base64 и хранит непустые байты в `audio.data`.
  `Audio.open()` создаёт новый `BytesIO`; вызывающий код закрывает его после чтения сегментов.
- `Task.from_dict()` проверяет поля и ID, создаёт объект `Audio` в `task.audio`; `Task.transcribe(model, language)`
  сохраняет склеенный текст в `task.text` и возвращает `None`.
- `Batch.from_list()` и `Batch.from_json()` создают пачку и проверяют состав и ID.
  `Batch.transcribe(config)` сбрасывает старые результаты, загружает одну модель,
  вызывает задачи и сохраняет словарь в `batch.results`; возвращает `None`.
- `Batch.write()` печатает `batch.results` в stdout с читаемой кириллицей.
  Сам метод не проверяет готовность: `main()` вызывает его после `transcribe()`.
- `ConfigError`, `TaskError` и `BatchError` наследуют `ValueError`. Общая функция
  `_fields` проверяет точный набор ключей и принимает нужный класс ошибки.

При ошибке чтения конфига, входа, загрузки модели или распознавания `main()`
пишет `transcribe: <описание>` в stderr и возвращает `1`. Ошибки аргументов
обрабатывает argparse с кодом `2`. Если любая задача падает, JSON с частичными
результатами не выводится. Повторы и разделение пачки воркер не выполняет.

Python-вывод библиотек во время загрузки модели и распознавания перенаправляется
из stdout в stderr через `redirect_stdout`; прямую запись нативных библиотек
в файловый дескриптор этот механизм не перехватывает.


## Проверки

Из каталога воркера:

```bash
PYTHONPATH=src ~/whisper-venv/bin/python -m unittest discover -s tests -v
mypy --config-file mypy.ini
```

Локальный `mypy.ini` включает строгую проверку `src` и `tests` независимо от
воркера embed. Зависимости разработки перечислены в `requirements-dev.txt`.
Контрактные тесты подменяют модель, не загружают веса и не требуют GPU.
Реальное распознавание проверяется отдельно на подготовленном `large-v3-turbo`.
