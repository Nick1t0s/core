# Воркер transcribe

Распознаёт локальные аудиофайлы через faster-whisper. Один запуск принимает одну
пачку через stdin, загружает модель один раз и последовательно обрабатывает файлы.
HTTP API у воркера нет. Он не скачивает входные файлы, не изменяет и не удаляет их.

## Файлы и запуск

```text
transcribe/
├── .venv/
├── src/
│   ├── main.py
│   ├── batch.py        # Task и Batch
│   ├── config.py
│   └── validation.py
├── config.yaml         # локальный конфиг, исключён из Git
├── config.example.yaml
├── requirements.txt
└── README.md
```

Зависимости указаны в [requirements.txt](requirements.txt). Окружение `.venv`
локальное, в Git не хранится. Из каталога `transcribe`:

```bash
.venv/bin/python src/main.py --config config.yaml < batch.json
```

`--config` обязателен. Другие рабочие CLI-параметры отсутствуют; `--help`
показывает справку. Пути к конфигу и файлу `batch.json` могут быть абсолютными
или относительными к текущему рабочему каталогу. Путь к аудио внутри пачки
обязательно абсолютный. Скрипт запускается напрямую через `src/main.py`.

## Конфигурация

Все четыре поля YAML обязательны, неизвестные поля запрещены, значений
по умолчанию нет. [Пример](config.example.yaml):

```yaml
model: large-v3-turbo
device: cuda
compute_type: float16
language: null
```

`model` — имя модели или локальный каталог, `device` — `cuda`, `cpu` или `auto`,
`compute_type` — непустая строка типа вычислений CTranslate2. Для CPU можно
указать `device: cpu` и `compute_type: int8`. `language: null` включает
автоопределение языка; строка вроде `ru` задаёт язык явно. Проверка конфига
проверяет форму значений, поддержка модели, языка и типа вычислений проверяется
библиотекой при работе.

Модель создаётся с `local_files_only=False`: при отсутствии локальных весов
библиотека может скачать их в свой кеш. Повторные запуски используют кеш.

## Вход и выход

В stdin передаётся один JSON-массив UTF-8, затем stdin закрывается:

```json
[
  {"task_id": "1", "path": "/tmp/audio-1.flac"},
  {"task_id": "2", "path": "/tmp/audio-2.flac"}
]
```

Пачка непустая. У каждой задачи ровно два поля: `task_id` — непустая строка,
уникальная в пачке, `path` — строка с абсолютным путём к существующему файлу.
Поля `type`, `input` и `mime` не передаются. Одна задача передаётся массивом
из одного элемента. Вся пачка проверяется до импорта faster-whisper и загрузки модели.

При успехе код завершения — `0`, stdout содержит один JSON-объект:

```json
{
  "1": "[00:01:10] Сегодня мы поговорим про нейросети.\n[00:01:15] Рассмотрим, как работают эмбеддинги.",
  "2": ""
}
```

Ключ — исходный `task_id`, значение — текст. Каждый непустой сегмент Whisper
начинается с новой строки с таймкодом `[ЧЧ:ММ:СС]` относительно начала входного
аудиофайла. Доли секунды отбрасываются. Границы строк определяются сегментами
модели, а не отдельным разбиением на предложения. Пробельные символы внутри
сегмента заменяются одиночными пробелами; пустые сегменты пропускаются.
В JSON переносы строк записаны как `\n`, после разбора JSON это обычные переносы.
Без распознанной речи результат — пустая строка.

Тип хранилища результатов также допускает `None` (в JSON — `null`), но текущий
успешный `Task.transcribe()` всегда записывает строку, включая пустую.
Внешних обёрток `results` и `payload` в stdout нет.

## Классы и ошибки

- `Task.from_dict()` проверяет поля, ID и путь; `Task.transcribe(model, language)`
  сохраняет склеенный текст в `task.text` и возвращает `None`.
- `Batch.from_list()` и `Batch.from_json()` создают пачку и проверяют состав и ID.
  `Batch.transcribe(config)` сбрасывает старые результаты, загружает одну модель,
  вызывает задачи и сохраняет словарь в `batch.results`; возвращает `None`.
- `Batch.write()` печатает `batch.results` в stdout с читаемой кириллицей.
  Сам метод не проверяет готовность: `main()` вызывает его после `transcribe()`.
- `ConfigError`, `TaskError` и `BatchError` наследуют `ValueError`. Общая функция
  `_fields` проверяет точный набор ключей и принимает нужный класс ошибки.

При ошибке чтения конфига, входа, загрузки модели или распознавания `main()`
пишет `transcribe: <описание>` в stderr и возвращает `1`. Ошибки аргументов
обрабатывает argparse с кодом `2`. Если любая задача падает, JSON с частичными
результатами не выводится. Повторы и разделение пачки воркер не выполняет.

Python-вывод библиотек во время загрузки модели и распознавания перенаправляется
из stdout в stderr через `redirect_stdout`; прямую запись нативных библиотек
в файловый дескриптор этот механизм не перехватывает.
